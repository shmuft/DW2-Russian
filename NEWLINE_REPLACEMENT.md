# Замена переносов строк на \n в переводимых XML файлах

## Описание проблемы
В переведённых XML файлах часто содержатся actual newline characters (реальные переносы строк). Это может вызвать проблемы с обработкой и отображением текста. Требуется автоматическая замена этих переносов на literal `\n` (две символа: backslash и 'n').

## Решение

### 1. Автоматическая замена при переводе
Код уже содержит автоматическую замену в функциях перевода:

**файл: translate.py**
- **Строка 148**: `translate_text()` - заменяет `\n` на `\\n` 
- **Строка 238**: `_translate_with_host()` - то же самое для удалённого пула

Это означает, что все НОВЫЕ переводы будут автоматически иметь escaped newlines.

### 2. Постобработка существующих файлов
Для исправления уже переведённых файлов добавлены новые функции:

**файл: translate.py** (новые функции):
- `fix_newlines_in_xml_file(xml_file: str)` - обработка одного XML файла
- `fix_newlines_in_directory(directory: str)` - обработка всех XML файлов в директории

## Использование

### Способ 1: Постобработка через translate.py
```bash
python3 translate.py 1.3.4.3/Russian --fix-newlines --type xml
```

### Способ 2: Постобработка через batch_translate.py (РЕКОМЕНДУЕТСЯ)
```bash
python3 batch_translate.py --fix-newlines
```

Эта команда обработает все XML файлы в директории `1.3.4.3/Russian` рекурсивно.

## Технические детали

### Как работает замена
```python
# До: actual newlines
text = "Строка 1\nСтрока 2"  # содержит chr(10)

# После: literal \n
text = "Строка 1\\nСтрока 2"  # две символа: chr(92) и chr(110)

# При записи в XML файл:
# <Description>Строка 1\nСтрока 2</Description>
# (в файле буквально видны символы '\' и 'n')
```

### Поддерживаемые типы переносов
- Одиночные переносы `\n` → `\\n`
- Двойные переносы `\n\n` → `\\n\\n`
- Все переносы в любых text элементах
